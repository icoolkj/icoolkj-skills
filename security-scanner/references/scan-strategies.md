# 扫描策略详解

## 策略对比

| 维度 | quick | standard | deep |
|------|-------|----------|------|
| 文件名特征检测 | ✅ | ✅ | ✅ |
| 文件头签名检测 | ✅ | ✅ | ✅ |
| 文件哈希计算 | ❌ | ✅ | ✅ |
| 脚本内容模式匹配 | ❌ | ✅ | ✅ |
| 压缩包内容检查 | ❌ | ❌ | ✅ |
| PE 结构分析 | ❌ | ❌ | ✅ |
| 递归子目录 | ✅ | ✅ | ✅ |
| 预计速度（1000 文件） | < 5 秒 | 10-30 秒 | 1-5 分钟 |
| 适用场景 | 快速排查 | 日常扫描 | 深度安全审计 |

## quick 策略

**检测项**：文件名特征 + 文件头签名

**适用场景**：
- 检查单个文件是否可疑
- 快速浏览目录中是否有明显威胁
- 时间紧迫的初步排查

**优势**：速度最快，几乎无 I/O 开销（仅读取文件前 64 字节）

**局限**：
- 无法检测脚本中的危险代码
- 无法检测哈希匹配的已知恶意样本
- 无法检查压缩包内部内容

**执行流程**：
```
遍历目标目录
  → 对每个文件读取前 64 字节
  → 检查文件名特征（双扩展名、可疑命名）
  → 检查文件头签名是否与扩展名匹配
  → 分类记录结果
```

## standard 策略

**检测项**：quick 全部 + 文件哈希 + 脚本内容模式

**适用场景**：
- 日常安全扫描
- 扫描下载目录
- 扫描 U 盘
- 排查项目中的可疑脚本

**优势**：平衡速度与检测深度，覆盖大部分常见威胁

**局限**：
- 不检查压缩包内部内容
- 不分析可执行文件 PE 结构

**执行流程**：
```
遍历目标目录
  → quick 全部检测
  → 计算文件 SHA256 哈希
  → 与内置恶意哈希库比对
  → 对脚本文件（JS/PS1/VBS/BAT/PY/SH）读取内容
  → 匹配危险代码模式
  → 分类记录结果
```

## deep 策略

**检测项**：standard 全部 + 压缩包内容 + PE 结构分析

**适用场景**：
- 深度安全审计
- 检查可疑压缩包
- 分析可疑可执行文件
- 全面排查未知威胁

**优势**：检测最全面，覆盖压缩包内部和可执行文件结构

**局限**：
- 速度最慢
- 压缩包检查仅读取文件列表，不解压
- PE 分析为基本级别，不等同专业逆向分析

**执行流程**：
```
遍历目标目录（递归全部子目录）
  → standard 全部检测
  → 对压缩包（ZIP/RAR/7Z）读取内部文件列表
  → 检查压缩包内部是否有可疑文件
  → 对 EXE/DLL 解析 PE 头
  → 检查导入表中可疑 API 组合
  → 分类记录结果
```

## 策略选择建议

| 场景 | 推荐策略 | 原因 |
|------|----------|------|
| 用户说"快速检查一下" | quick | 时间优先 |
| 用户说"扫描下载目录" | standard | 平衡速度与深度 |
| 用户说"深度扫描" | deep | 深度优先 |
| 单个 EXE 文件检查 | quick | 单文件无需深度 |
| U 盘扫描 | standard | 外部设备需中等深度 |
| 可疑压缩包检查 | deep | 需检查内部内容 |
| Python 项目排查 | standard | 重点检查脚本内容 |
| 全盘扫描 | standard | 文件量大，deep 过慢 |
| 安全审计 | deep | 需要最全面检测 |

## 性能预期

| 目标规模 | quick | standard | deep |
|----------|-------|----------|------|
| 1 文件 | < 0.1 秒 | < 0.5 秒 | < 2 秒 |
| 100 文件 | < 1 秒 | 3-5 秒 | 10-30 秒 |
| 1000 文件 | < 5 秒 | 10-30 秒 | 1-5 分钟 |
| 10000 文件 | < 30 秒 | 2-5 分钟 | 10-30 分钟 |

注意：以上为预估时间，实际速度取决于磁盘 I/O 和文件大小。deep 策略对大文件（> 100MB）的 PE 分析可能显著增加耗时。
