# 异步工作流与请求竞态

本文规定页面加载、表单提交、行操作、权限编辑和组织切换的最小状态模型。

## 状态分层

不要用一个全局 `loading` 锁住整页。至少区分：

- `initialLoading`：第一次进入页面时加载主数据。
- `refreshing`：保留现有数据时重新请求。
- `submitting`：当前表单提交。
- `rowActionId`：某一行正在执行的操作。
- `detailLoading`：选中记录的详情或权限。
- `scopeChanging`：组织或数据范围正在切换。

不同状态应只影响相关控件。导航、取消和不相关的查看操作不应被无端冻结。

## 请求生命周期

每个异步操作都要明确：

1. 触发条件和前置校验。
2. 开始时清理哪些旧状态。
3. 请求中哪些控件禁用。
4. 成功后更新哪个本地列表或基线。
5. 失败后保留哪些输入和重试入口。
6. 请求结束时如何恢复可操作状态。

`finally` 必须恢复对应状态。处理函数本身也要检查进行中状态，不能只依赖模板的 `:disabled`。

## 防止过期响应

对于组织、路由、搜索词、选中角色或选中记录变化的请求，使用 request id 或 AbortController：

```ts
const requestId = ++latestRequestId
const response = await api.get(url)
if (requestId !== latestRequestId) return
apply(response.data)
```

旧响应不能覆盖新范围、新选中项或新搜索条件。切换上下文时先清空旧列表或将其标记为不可操作。

## 错误分类

- `401`：清理会话并跳转登录，不在页面重复弹无意义错误。
- `403`：说明当前用户没有权限，保留页面上下文但隐藏/禁用不可用操作。
- `404`：资源或范围不存在，提供返回列表或重新加载入口。
- `409`：冲突，例如编码重复；保留表单并指出冲突字段。
- `422`：字段校验失败；优先映射到字段，而不是只显示通用消息。
- 超时/网络错误：保留输入，允许重试并说明服务状态。

## 保存与基线

权限、设置和编辑表单需要保存基线：

- 当前值与已保存值不同才进入 dirty 状态。
- 保存时提交快照，避免请求期间继续变更造成结果不确定。
- 成功后以服务端返回值作为新基线。
- 切换对象、组织或路由前检查 dirty 状态。
- 失败时保留当前修改，允许重新提交。

## Element Plus 落地

- 使用 `el-button :loading`，同时在 handler 中防重复。
- 页面初次加载优先 `el-skeleton`，已有数据刷新优先保留数据并显示刷新状态。
- 对话框提交失败不自动关闭；成功后关闭并刷新关联列表。
- 行级操作使用 keyed state，避免一行保存时锁住整个表格。
- `ElMessage` 只传达结果；需要用户修复输入时使用字段错误或 `el-alert`。
