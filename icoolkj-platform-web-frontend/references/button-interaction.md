# 按钮行为与反馈规范

本文规定 icoolkj-platform Web 应用按钮和操作控件的默认行为。目标是让操作可预测、可恢复、可访问；动效是可选表达，不是完成度指标。

## 默认原则

- 先确认操作是否真实可用：按钮必须对应已实现的路由、前端状态变化或后端 API。占位模块不放会误导用户的新增、保存或发布按钮。
- 用 `el-button` 等现有 Element Plus 控件，保留其键盘、焦点和禁用行为。不要仅为统一视觉而新建全局按钮封装。
- 每个页面工作区只设一个主要动作；次要动作降级呈现，危险动作明确标识。按钮文案使用动词并说明对象，例如“创建员工账号”“保存权限”。
- 高频导航、表格行内操作和密集工具栏使用即时、克制的状态反馈，不加位移、磁吸、涟漪或弹簧动画。
- 不用颜色或动画代替状态文字、错误说明和操作结果。

## 操作状态契约

| 状态/结果 | 默认行为 | 不要这样做 |
|---|---|---|
| 可操作 | 清晰的动词标签；一个主操作突出即可 | 同一工作区放多个同等强调的主按钮 |
| Hover / Focus / Pressed | 保留 Element Plus 默认反馈；键盘焦点清晰可见 | 删除 outline，或用夸张位移提示点击 |
| Disabled | 仅在确实不可操作时禁用；在字段旁或按钮附近说明条件 | 所有禁用原因都藏在 tooltip，尤其是触屏场景 |
| Loading | 异步请求期间显示 loading 并阻止重复提交；只锁定相关操作 | 整页冻结，或请求结束后仍保持 loading |
| Failure | 解除 loading，显示可理解的错误和重试方式；保留用户已输入内容 | 清空表单、只留下按钮变红、吞掉错误 |
| Success | 更新列表/状态并就近提示；必要时关闭已成功提交的对话框 | 把对勾动画当作唯一成功信号或永久按钮状态 |

不是每个按钮都需要全部状态：导航不需要 loading；同步的展开/选择只需要选中状态；异步提交才需要 loading 和失败恢复。失败属于操作反馈，不是必须维持的按钮模式。

## 按操作类型设计

| 操作 | 按钮和流程 | 风险/实现约束 |
|---|---|---|
| 页面导航 | 使用路由链接语义；标明当前导航位置 | 不显示请求 loading；刷新和直达路由仍需保持选中态 |
| 新建/提交 | 弹窗或页面内表单；字段校验；提交按钮 loading、防重复；成功后刷新相关数据 | 后端校验失败时保留表单并定位问题 |
| 保存设置/权限 | 仅在存在未保存修改时启用；保存中锁定本次保存；成功后更新基线 | 切换对象或离开页面前提示未保存修改 |
| 表格行操作 | 动作短而明确；只让当前行进入 loading | 高频操作不用复杂动画；图标按钮提供可访问名称和 tooltip |
| 分配/切换 | 提交前显示当前值和目标值；异步时锁定当前记录 | 反馈后同步当前状态，避免用户重复分配或误认为已撤销 |
| 删除/停用/重置 | 明确目标、影响和可恢复性；用确认对话框；若有撤销能力则给撤销入口 | 不默认采用长按；无后端 API 时不显示该动作 |
| 占位模块 | 说明当前未接入的功能边界 | 不提供会让用户误以为可执行的 CTA |

## Vue / Element Plus 落地

- 异步按钮优先使用 `:loading="saving"`；提交处理函数也要检查同一状态，避免键盘提交或快速点击绕过 UI 锁定。
- 表单按钮可根据真实校验结果禁用；同时保留字段级提示，告诉用户还缺什么。
- 失败提示使用 Element Plus `ElMessage` 或字段级 `el-alert`，就近且简洁；保留输入，不用“按钮抖动”代替解释。
- 长列表的单行操作用按行 keyed loading 状态，避免一个请求锁住所有记录。
- 只有当至少多个页面共享相同业务状态和行为时，才抽 `ActionButton`/composable；样式相似本身不足以抽象。
- 组织权限按钮可以按已知上下文隐藏或禁用，但后端授权仍是唯一安全边界；处理服务端 403 并提供清晰反馈。

## 可访问性与动效

- 保留 Tab、Enter/Space、Esc 等原生控件交互，焦点状态必须可见。重要操作用可见文字；纯图标按钮提供 `aria-label` 和 tooltip。
- 为 `prefers-reduced-motion` 用户减少装饰性位移、弹跳、形变和涟漪；不能隐藏 loading、成功、错误等必要状态信息。
- 如需动画，先证明它能帮助识别状态或空间关系。微交互通常控制在 150–200ms；不以“每个按钮都动”为目标。
- 任何动效不得成为执行操作的唯一方式；触屏、键盘和辅助技术用户须有等价操作路径。

## 可选动效目录（非默认）

仅在用户明确要求、目标场景合适且通过键盘/触屏/减少动态效果检查后，才考虑以下实验。必须避免与 Element Plus 内置交互重复。

### 按压回弹

按钮按下时轻微缩小，松开后回到原位。仅适用于少量、低频的展示型主操作；不用于表格行、导航和危险操作。

### 磁吸悬停

按钮随鼠标指针轻微位移。仅适用于桌面工作台的少数引导 CTA；触屏没有等价 hover，故不能承载功能或状态。

### Loading 转完成图标

可在短暂保存流程中探索 spinner 与完成图标的轻量切换，但仍需保留文字/区域状态或消息；失败时必须恢复可重试状态。不是保存按钮的默认实现。

### 长按触发

不作为删除的替代确认。若特定设备工作流确实需要长按，仍须提供键盘可用的确认路径，并验证触屏辅助能力和取消行为。

### 点击涟漪

仅在自定义控件且默认反馈不足时考虑；不要叠加在 Element Plus 已有点击态上。

## 检查清单

- 按钮是否有明确对象和结果，并且实际可执行？
- 异步操作能否防重复、显示等待、失败可恢复且不丢输入？
- 成功反馈是否与数据更新一致，而非只有动画？
- 禁用、危险、图标操作的原因/影响是否可理解？
- 键盘焦点、触屏和 `prefers-reduced-motion` 是否仍可用？
- 高频操作是否避免了不必要的动效？
