# 设计方向手册（V1.3.0）

同一任务、同一内容，换一个版式骨架就会得到“看起来像另一个技能”。本文件用于在写 HTML 前先锁定方向，并为每次交付留下可核对的版式指纹。

## 1. 四个基本方向

| 代号 | 方向 | 版式骨架 | 配色 | 字体 | 适合 |
|---|---|---|---|---|---|
| D1 | 现代工具 | 单侧深色栏 + 横向流程 + 参数条 | 深蓝/青绿 + 明亮底 | 无衬线标题 | 软件工具、功能单页 |
| D2 | 档案卷宗 | 纸面细线网格 + 编号目录 + 印章 | 米色纸底 + 藏青 + 朱红 | 宋体标题 + 等宽编号 | 档案、政务、专业服务 |
| D3 | 技术白皮书 | 纯白 + 大留白 + 单列数据表 | 单色蓝/灰 + 极少量强调 | 无衬线，克制字号 | 企业软件、方案说明 |
| D4 | 品牌海报 | 全幅主视觉 + 大标题 + 少量文字 | 高对比或品牌色 | 标题主导 | 活动、品牌氛围（不适合长字段表） |

方向不是模板库，四者只是起点；允许在 D2 上做变体，但必须记录变体名（如 `D2-卷宗-横版`）。

## 2. 选择规则

1. 先按内容密度排除：字段表、流程、精确数字超过 8 条时，排除 D4；信息总量少且无表格时才考虑 D4。
2. 再按行业调性选：档案/政务优先 D2；软件工具在 D1 与 D3 之间选；金融/企业服务偏 D3。
3. 系列优先：同一客户已交付过某方向时，第二张沿用同一方向，只换内容结构；跨系列换方向要记录原因。
4. 多方案请求：每个方案必须落在不同方向，不能同一骨架换色。方案命名用 `poster-01-d1.html`、`poster-01-d2.html`，不要用 `v001/v002` 冒充设计方向。
5. 迭代修正（改字、改价）沿用同方向，用 `v002` 递增，并在记录中写 `direction` 与 `based_on`。

## 3. 写代码前的方向卡

在动手前用 6 行记录，随任务目录保存为 `direction.md`：

```text
方向：D2-卷宗
版式：纸面细线网格，无大色块
配色：F4F1E8 / 1F3A5F / A6432B
标题字体：Noto Serif CJK SC
正文/编号：Noto Sans CJK SC / Noto Sans Mono CJK SC
与上一版的差异：上一版 D1 深色侧栏；本版改为浅纸底与细线表
```

方向卡不是交付给客户的内容，只用于避免下一轮重复自己。

## 4. 防重复红线

- 同一客户、同一内容，第二次交付不得与上一版共享“版式骨架 + 主色 + 标题字体”三项；至少替换两项。
- 不允许只改颜色、字号或不换骨架就宣称“新方案”。
- 生成后必须用 `--compare` 对比上一版；判定 `reuse` 时重做，不得用 `--allow-reuse` 掩盖偷懒。
- 交付记录写 `production.direction`，校验器要求 html_render 记录该字段；缺失时按不完整记录处理。

## 5. 与检查器的分工

- `scripts/check_html_poster.py --compare <上一版.png>`：计算深色占比、主色直方图、行密度与边缘密度，输出 `similarity` 与 `verdict`（`distinct` / `related` / `reuse`）。
- 相似度只用于发现“版式重复”，不判断美丑；`related` 表示同系列可接受，`reuse` 表示必须换方向。
- 数值阈值：`>= 0.86` 判 `reuse`，`0.72–0.86` 判 `related`，`< 0.72` 判 `distinct`。
