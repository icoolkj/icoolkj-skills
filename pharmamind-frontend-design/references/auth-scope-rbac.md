# 认证、组织范围与 RBAC

本文用于 Vue 3 后台项目的身份上下文和权限交互设计。前端只负责建立可理解的体验；后端授权、组织范围查询和资源 ACL 才是安全边界。

## 三种上下文

必须区分以下三个概念：

1. **Session identity**：当前登录用户、账号状态、是否超级管理员、可访问组织集合和权限集合。
2. **JWT active organization**：服务端签发在当前 access token 中的组织上下文，可能影响后端权限计算。
3. **Page data scope**：当前页面用于筛选和查看数据的组织范围，可以是当前组织、授权下级组织或某个业务范围。

不要把一个 `localStorage` 的组织 id 同时当作这三种状态。浏览器存储只能恢复便利性选择，不能授予权限。

## 启动与路由

- 有 token 不代表会话有效。应用启动时应读取当前用户接口，建立 session store；失效 token 进入登录流程。
- 路由元数据声明所需权限或能力。菜单可据此隐藏，但直接访问仍由 router guard 和后端共同处理。
- 401 表示会话失效，清理本地会话并回到登录页；403 表示会话有效但无权，进入明确的无权页面或保留当前页面并显示原因。
- 未知路由、已登录访问登录页、无权限路由和后端 404 应有不同的页面结果。

## 组织切换

先确定产品语义：

- 如果只是页面筛选，使用 page data scope，并重新加载所有关联列表。
- 如果要改变 JWT 权限上下文，调用服务端切换组织接口，保存新 token，再刷新用户、菜单和所有组织数据。

组织切换流程必须：

1. 禁止重复切换。
2. 清除或冻结旧范围下的列表和行操作。
3. 取消或标记旧请求，使旧响应不能覆盖新范围。
4. 成功后刷新组织树、用户权限和当前页面数据。
5. 失败后恢复原范围并说明原因。

## 菜单与权限

- 菜单权限是可用性层，不是安全措施。
- 页面权限、按钮权限和数据范围权限分别建模；能进入页面不代表能执行页面内所有动作。
- 组织角色、全局系统角色、继承权限和只读角色必须有不同的视觉和操作语义。
- 无后端 API、无权限依赖或没有明确组织校验的操作不显示为可执行按钮。
- 角色绑定页面必须区分“当前已有角色”“追加角色”“替换角色”和“解除角色”。

## 后端联审清单

每个新增或暴露的操作都要确认：

- 后端是否有对应方法和响应结构。
- 是否检查用户权限。
- 是否检查目标组织在当前授权范围内。
- 是否检查目标用户、角色、资源属于正确组织。
- 全局资源是否允许当前操作。
- 冲突、越权、资源不存在和校验失败分别返回什么。
- 是否需要审计、撤销或可恢复机制。

## 推荐实现边界

建议使用一个 session composable/store 管理用户、token 生命周期、权限和组织上下文；使用一个 scope composable 管理页面数据范围和请求失效；页面组件只消费状态并发起业务操作，不重复解析 token 或复制权限判断。
