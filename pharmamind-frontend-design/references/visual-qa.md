# 响应式与视觉验收

视觉验收不是“看起来差不多”，而是检查信息层级、交互可达性和不同宽度下的稳定性。

## 视口矩阵

至少检查：

- **1440px 以上**：符合条件的模块是否正确呈现左中右，右侧工作区是否有足够宽度。
- **1024px**：二级菜单是否降级为紧凑横向导航或窄栏，表格仍可读。
- **768px**：主从内容是否合理堆叠，页面标题、组织范围和主操作是否仍可达。
- **390px**：一级菜单是否可折叠/滚动，弹窗和表单是否不超出屏幕，表格是否只在容器内滚动。

## 必查项目

- 当前路由刷新后一级、二级菜单仍正确激活。
- 页面标题、描述、组织范围和主按钮没有互相挤压或重叠。
- 中栏只承担二级导航，不重复显示页面内容或记录列表。
- 角色列表、文档列表等页面的左右主从区在窄屏下不会出现不可达详情。
- loading、错误、空状态和无权限提示不会撑坏布局。
- 按钮文案、表头、标签和错误信息在窄屏可读，不被截断到无法理解。
- Tab、Enter/Space、Esc 和焦点顺序可用；焦点不会被弹窗关闭或导航切换吞掉。
- `prefers-reduced-motion: reduce` 下不依赖位移、回弹或涟漪完成反馈。

## 交付证据

前端改动较大时，记录至少一项可复核证据：生产构建、测试结果、桌面/移动截图或录屏。截图只用于证明真实实现，不用静态设计图代替运行页面检查。
