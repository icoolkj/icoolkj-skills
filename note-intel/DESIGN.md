# NoteIntel v1.0 架构设计

## 定位

NoteIntel 把文章、资料、网页、采访和多份来源转化为可核对、可比较、可继续创作的自媒体内容情报包。它不是固定数量的摘要器，也不是无证据的标题生成器。

## 设计决策

1. **证据链优先**：来源登记 → 原文定位 → 引用片段 → 事实 ID → 选题 ID。
2. **弹性配额**：篇幅与密度决定建议区间；最小值是软提示，最大值是硬上限；证据不足可以少于下限或为零。
3. **语义分层**：事实、原文观点、推断、核查缺口、风险和来源冲突分开保存。
4. **JSON 为事实源**：Markdown 适合阅读，HTML 适合浏览，JSON 供继续创作、评分、合并和对比。
5. **安全合并**：精确重复才去重；数字、时间、口径或范围不同则保留并列并记录冲突。
6. **创作可执行**：选题必须关联事实，并附价值增量、图文骨架、视觉计划、证据边界和下一步动作。

## 数据流

```text
输入 → 来源登记 → 清洗/分析 → 候选证据 → 事实/观点/推断分层
     → 选题与图文骨架 → 风险/核查 → JSON校验 → MD/HTML导出
     → （可选）评分 / 多素材合并 / 来源对比
```

## 主要模块

| 模块 | 责任 |
|---|---|
| `analyze_material.py` | URL/文件/文本清洗、篇幅和密度分析、建议模式与配额 |
| `extract_candidates.py` | 候选事实、段落/句子定位和优先级 |
| `scan_risks.py` | 预测、时效、单一来源、利益相关、敏感和观点风险 |
| `validate_json_pack.py` | 新版 JSON 数据契约、来源、事实 ID、选题关联校验 |
| `validate_pack.py` | Markdown 结构、引用、原文可追溯、弹性配额校验 |
| `export_pack.py` | JSON 保真导出及 MD/HTML 可读视图 |
| `score_topics.py` | 增量价值、传播潜力、创作难度和证据覆盖评分 |
| `merge_packs.py` | 事实去重、来源保留、事实编号重映射和冲突候选 |
| `compare_packs.py` | 事实、选题、引用及覆盖差异 |

## 输出原则

没有内容的可选模块不输出；没有证据的选题不输出；不把预测改写为事实；不把单一来源标成已核验；不把两份不同口径的数字平均或拼接。所有动态数量都由素材实际支撑能力决定。
