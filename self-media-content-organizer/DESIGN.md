# 自媒体内容整理 v1.0 架构设计

## 核心定位

平台无关的内容整理与再创作中台：先形成可核对的事实底座，再按微信公众号、小红书、知乎、视频号/抖音、朋友圈等平台适配表达。

## 数据流

```text
文章/报告/网页/采访/帖子/图片
  → 来源登记与边界
  → 文本/图片分析
  → 事实、观点、推断分层
  → 风险、版权、冲突检查
  → 通用内容素材包
  → 平台适配器
  → 文案/脚本/卡片方案/视觉成品
```

## 三层结构

1. **内容情报层**：来源、事实、证据、观点、推断、风险、核查缺口、多素材冲突。
2. **视觉资产层**：原文图片、整理图、AI示意图、平台成品和版权状态。
3. **平台适配层**：微信公众号、小红书、知乎、视频号/抖音、朋友圈；平台只改变表达，不改变事实。

## 关键决策

- JSON 是事实源；Markdown、HTML、平台文案和图片方案是视图。
- 配额下限是软提示，最大值是硬约束；证据不足允许少于下限或为空。
- 原文图片不等于可公开发布；整理图必须关联事实；AI图不能当证据。
- 精确数字和表格优先使用确定性图表/静态布局，不用AI凭空绘制。
- 用户未指定平台时先交付通用素材包并给出平台建议，不擅自默认小红书。
- 用户未明确要求生成图片时先交付视觉方案和卡片结构，再进入成品制作。

## 现有脚本复用

`analyze_material.py`、`extract_candidates.py`、`scan_risks.py`、`validate_json_pack.py`、`validate_pack.py`、`export_pack.py`、`score_topics.py`、`merge_packs.py`、`compare_packs.py` 继续提供底层分析、校验、导出、评分、合并和对比能力。
