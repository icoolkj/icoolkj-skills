# 常见问题排查

## 一、Word 提示「文件已损坏，是否修复」

这说明某个 XML 部件的结构不合规。转换脚本默认会在写盘后做一次严格自检，
正常情况不会出现。若出现，按顺序排查：

1. 重新执行，看是否报 `结构自检：发现 N 个问题`，问题描述会直接指出是哪个部件、哪类元素顺序错了。
2. 用 `python scripts/dualdoc.py verify 文件.docx` 复核。
3. `--no-validate` 只是跳过检查，不解决问题，不要用它绕过。

常见根因是手工改过 `scripts/docxkit.py` 里拼接 XML 的字符串，把 `pPr` / `rPr` 的子元素顺序打乱了。
OOXML 对顺序敏感，顺序表见 `docxkit.py` 里 `RPR_ORDER` / `PPR_ORDER` 常量。

## 二、docx2md 取回的内容不是原文

`docx2md` 有两条路径，看输出里的「来源」一行：

- `隐藏层（无损）`：直接解出原文，说明这份 docx 是本工具生成的且隐藏层完好。
- `结构化反解（普通 docx）`：说明没有隐藏层，内容是按样式推断的。

隐藏层丢失的典型原因：

| 场景 | 结果 | 对策 |
| --- | --- | --- |
| 用 WPS / Word 打开后另存为「纯 docx」 | 自定义部件可能被丢弃，隐藏文字通常保留 | 隐藏文字是第二重保险，一般仍可解出 |
| 上传到在线文档（飞书/腾讯文档/Google Docs）再导出 | 两层都会丢 | 只能走结构化反解，或从原始 md 重新生成 |
| 用第三方工具做了格式重排 | 同上传 | 同上 |

判断当前文件状态：`python scripts/dualdoc.py verify 文件.docx`，会分别列出
「自定义部件」和「隐藏文字」两层的检查结果。

## 三、代码块的缩进对齐在 Word 里错乱

代码块用 Consolas 渲染 ASCII 图，中文等宽靠 `宋体` 兜底。混排中英文的 ASCII 图
（比如框线图里夹着汉字）在 Word 里很难做到与等宽终端完全对齐，这是字体度量差异，
不是转换错误。建议：

- 纯英文/符号的框线图 → 对齐良好
- 中英混排的框线图 → 可接受轻微错位，不影响阅读
- 需要严格对齐 → 改成图片贴进 md

## 四、表格列宽不均匀

表格用 `tblW=5000`（占版心 100%）+ `autofit`，由 Word 按内容自动分配列宽。
若某列内容特别长，会被拉宽。需要固定列宽时，改 md 里单元格内容长度是最省事的办法。

## 五、标题没有出现在 Word 导航窗格里

标题必须走 `Heading1~4` 样式且带 `outlineLvl` 才会进导航窗格。本工具生成的标题都带。
如果从别处复制内容进来，注意不要用「直接加粗放大」冒充标题。

## 六、`--toc` 生成的目录是空白的

目录是 Word 的域（field），需要 Word 计算后才有内容。打开文档后：

- 右键目录区域 →「更新域」→「更新整个目录」
- 或按 `Ctrl+A` 后按 `F9`

## 七、图片报了「未找到」

图片路径相对 **md 文件所在目录**解析。外链图片（`http(s)://`）不会去下载，
会在 Word 里显示为 `[说明文字]` 占位，并在转换结束时给出提示。

## 八、想彻底去掉隐藏层

```bash
python scripts/md2docx.py 文档.md --embed-mode none
```

代价是这份 docx 再也无法无损取回 Markdown，只能结构化反解。
对外分发、不希望别人看到源码时可以用这个参数。
