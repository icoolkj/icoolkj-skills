# 标签体系参考规范

## 核心原则：动态生成

分类维度不预设固定模板，而是由 Agent 在 Phase 2 根据当前文件集的内容特征动态归纳。

## 归纳流程

### 1. 采样分析

Agent 读取 scan-result.json 中所有文件的 `title` 和 `summary` 字段，分析内容特征。

### 2. 维度归纳

根据内容特征，归纳出 2~5 个分类维度。归纳依据：

- **文件集主题集中度高**（如全是小红书文案）→ 维度应更细化
  - 可能维度：内容主题、发布状态、文案风格、目标受众
- **文件集主题分散**（如混合工作文档、个人笔记、素材包）→ 维度应更概括
  - 可能维度：文档类型、所属项目、重要程度
- **文件集以图片为主** → 维度应包含视觉特征
  - 可能维度：图片类型（封面/内容图/截图）、用途、主题

### 3. 维度质量检查

每个维度应满足：
- **区分度**：不同文件应能分到不同标签值，不能所有文件都是同一个值
- **覆盖度**：绝大多数文件都能归入某个标签值，不能大量"无法分类"
- **粒度适中**：3~10 个可选值，太少（2个）区分度不够，太多（>10个）认知负担重

### 4. 可选维度参考

以下维度仅供参考，实际维度由 Agent 根据文件内容决定：

| 维度 | 适用场景 | 可选值示例 |
|------|---------|-----------|
| 内容主题 | 任何文件集 | AI、职场、教程、测评、生活、理财 |
| 文档类型 | 混合文件集 | 文案、素材包、报告、笔记、方案、会议纪要 |
| 发布状态 | 创作类文件 | 草稿、进行中、待发布、已发布、已归档 |
| 文案风格 | 小红书文案 | 干货型、故事型、盘点型、对比型 |
| 目标平台 | 多平台创作 | 小红书、公众号、知乎、抖音、视频号 |
| 重要程度 | 工作文档 | 高、中、低 |
| 所属项目 | 项目文档 | 项目A、项目B、通用 |
| 图片类型 | 图片为主 | 封面图、内容图、数据图、截图 |

## 置信度规则

| 置信度 | 标准 | 处理方式 |
|--------|------|---------|
| high | 摘要中有明确证据支撑该标签 | 直接采用 |
| medium | 摘要中有间接线索，但不完全确定 | 采用但标注 |
| low | 无法从摘要中判断 | 标记为"待确认"，列入报告 |

## 用户调整维度

用户可以在 Phase 4 报告后提出调整：
- "加一个'目标平台'维度" → Agent 重新归纳并补打标签
- "把'发布状态'改成'审核状态'" → Agent 更新维度定义并重新打标签
- "主题标签太粗了，细分一下" → Agent 重新归纳更细的主题维度

调整后 Agent 需要重新展示完整确认卡。
