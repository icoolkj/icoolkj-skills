# doc-manager

> 扫描、分类、索引、检索——让堆积的文档变得井然有序。

## 核心原则

1. **分类维度动态生成**——不预设固定标签体系，而是根据当前文件集的内容特征，由 AI 归纳出最适合的分类维度
2. **只读不写**——不修改、不移动、不删除用户的任何文件，只在指定目录下生成索引文件
3. **增量分类**——只对索引中没有标签的新文件分类，已分类的文件跳过，避免重复消耗
4. **脚本做机械工作，AI 做智能工作**——scan.py 负责文件遍历和摘要提取，分类维度归纳和标签打标由 Agent 完成

## 工作流

### Phase 1: 扫描

运行扫描脚本，获取文件清单：

```bash
python scripts/scan.py "<目标目录>" [--index-dir "<索引目录>"]
```

- `目标目录`：要整理的文档所在目录
- `--index-dir`：索引文件存放目录，默认为 `<目标目录>/.doc-manager/`

脚本输出 JSON 清单到 stdout，包含每个文件的：路径、文件名、扩展名、大小、修改时间、内容摘要（前500字）、.md 文件中的图片引用。

Agent 将输出保存为 `<索引目录>/scan-result.json`。

### Phase 2: 归纳分类维度

Agent 分析 scan-result.json 中所有文件的标题和摘要，归纳出 2~5 个适合当前文件集的分类维度。

归纳规则：
- 维度数量：2~5 个，不宜过多
- 每个维度有 3~10 个可选值
- 维度应贴合文件集的实际内容特征，不套用固定模板
- 如果文件集主题集中（如全是小红书文案），维度应更细化；如果主题分散，维度应更概括

将维度定义写入 `<索引目录>/index.json` 的 `taxonomy` 字段。

### Phase 3: 打标签

Agent 按 Phase 2 归纳出的维度，对每份文件打标签：

- 读取文件摘要（scan-result.json 中已提供，无需重新读取文件）
- 按每个维度给出标签值
- 对不确定的标签标注置信度：`high` / `medium` / `low`
- `low` 置信度的标签值标记为"待确认"
- 批量处理：一次可处理 10~20 份文件的分类
- 已有标签的文件跳过（增量分类）

将分类结果写入 `<索引目录>/index.json` 的 `documents` 字段。

### Phase 4: 输出报告

Agent 向用户输出分类统计报告：

- 归纳出的分类维度及各标签值分布
- 各文件类型的数量分布
- 低置信度文档清单（需人工确认）
- .md 文件中引用的图片资产统计

### Phase 5: 检索（按需）

用户后续说"找关于XX的文档"时，Agent 读取 index.json，按标签和关键词筛选，返回匹配结果（文件路径、标题、标签、摘要）。

## 决策规则

| 任务 | 执行方式 |
|------|---------|
| 文件遍历、摘要提取、图片路径解析 | 运行 scan.py |
| 分类维度归纳 | Agent 分析摘要后归纳 |
| 标签打标 | Agent 按维度逐份分类 |
| 索引读写 | Agent 使用 Read/Write 工具操作 index.json |
| 检索 | Agent 读取 index.json 后筛选 |

## 安全约束

**禁止**：
- 修改、移动、删除用户的任何原始文件
- 将索引文件写到目标目录之外（除非用户明确指定 `--index-dir`）
- 在索引中记录文件的完整内容（只记录摘要）

**优先**：
- 增量分类，避免对已分类文件重复处理
- 低置信度标签明确标记，不假装确定
- 索引文件使用 UTF-8 编码，确保中文内容正确
